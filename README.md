# Sob Carga

**Decisões reais de engenharia.**

Sob Carga é um podcast sobre engenharia de software, engenharia de dados, arquitetura e tomada de decisões técnicas.

A proposta é simples: em cada episódio, dois engenheiros recebem um problema e constroem uma solução diante da audiência.

Não existe arquitetura pronta.

O problema é apresentado, requisitos são levantados, restrições surgem, alternativas são discutidas e a arquitetura evolui ao longo da conversa.

O foco não está em ensinar uma ferramenta específica, mas em tornar visível o raciocínio por trás das decisões de engenharia.

## O formato

Cada caso segue, de maneira geral, este fluxo:

```text
Problema
   ↓
Restrições
   ↓
Alternativas
   ↓
Decisões
   ↓
Arquitetura
   ↓
Trade-offs
   ↓
Sob Carga
```

Tecnologias como Kafka, bancos de dados, APIs, cloud, microsserviços, pipelines, lakehouses e processamento distribuído aparecem somente quando fazem sentido para o problema.

## A proposta

Sob Carga parte de uma ideia central:

**não existem arquiteturas perfeitas. Existem decisões, contexto e trade-offs.**

O objetivo do projeto é transformar esse raciocínio em conteúdo acessível, visual e útil para profissionais de tecnologia.

Cada episódio busca mostrar:

- como um problema é interpretado;
- quais perguntas precisam ser feitas antes de escolher uma tecnologia;
- como restrições alteram uma arquitetura;
- por que uma solução pode ser correta em um contexto e errada em outro;
- quais trade-offs acompanham cada decisão.

## O site

O site funciona como extensão do podcast.

Além dos episódios em áudio e vídeo, cada caso pode ter sua própria página com contexto, arquitetura, decisões e referências.

Com o tempo, a proposta é formar uma biblioteca pública de problemas e decisões de engenharia.

## Estrutura do projeto

```text
sob-carga/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── main.js
├── assets/
│   └── img/
└── casos/
```

O site foi propositalmente construído com HTML, CSS e JavaScript puros.

A escolha reflete a própria filosofia do Sob Carga:

**não adicionar complexidade antes que o problema exija.**
